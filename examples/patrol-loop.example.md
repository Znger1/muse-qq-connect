# 最小巡查循环规格（patrol loop example）

这是一份**纯机械**的循环规格：把服务器端的 `patrol_pull.py`
接到任何"能按周期触发 + 能执行 SSH 命令"的环境（AI 助手的定
时任务、cron、systemd timer 均可），周期性地取回新消息的
JSON 行。

本文件只描述连接与数据流。**消息的筛选与提醒规则不在此列，
由使用者在助手侧自行定义。**

占位符：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `<qq-host>` | QQ 所在主机的 SSH 目标 | `root@192.0.2.10` |
| `<ssh-extra>` | 额外的 SSH 选项（跳板/代理/指定密钥等，没有就删掉） | `-i ~/.ssh/id_ed25519` |
| `<script-path>` | `patrol_pull.py` 在 QQ 主机上的绝对路径 | `/opt/qq-reader/patrol_pull.py` |

前置条件（部署细节见根目录 README 的"部署步骤"）：读取端已
部署到 QQ 主机、`key.json` 已生成、`patrol_pull.py` 已完成
首次运行（水位线初始化）。

---

## 循环步骤

1. **触发**：按你设定的周期（例如每 10 分钟）启动一轮。
2. **执行一条 SSH 命令**（脚本在 QQ 主机本地完成复制副本 →
   解密 → 增量提取，全程只读 QQ 本体、零网络）：

   ```bash
   ssh -o StrictHostKeyChecking=no <ssh-extra> <qq-host> 'python3 <script-path>'
   ```

3. **先读第一行状态行**（`type=status`），再逐行读消息行
   （`type=message`）。状态行字段与处理：

   | 字段 | 含义 | 本轮动作 |
   |---|---|---|
   | `status=OK` | 正常 | `new_messages` 为本轮新消息条数；逐行解析其后的消息行 |
   | `status=INIT` | 水位线刚初始化（仅首次出现） | 本轮无消息行，结束 |
   | `status=KEY_FAIL` | 钥匙失效且服务器端自动重取失败 | 见"异常处理" |
   | `status=ERROR` | 副本/解密/解析异常 | 见"异常处理" |
   | `qq_running=false` | QQ 主进程不在 | 见"异常处理" |
   | `db_mtime_cst` | 数据库副本的更新时间 | 若距当前时间过久（如超过 30 分钟），疑似 QQ 掉线/掉登录，见"异常处理" |
   | `key_recovered=true` | 脚本已在服务器端自动重扫内存、换用新钥并恢复 | 仅作记录，本轮照常处理消息行 |

   水位线由脚本在服务器端自己维护（`watermark.json`），不要
   手工修改；它保证每条消息只输出一次。

4. **逐行解析消息行**，交给助手（或你的程序）后续处理。字段
   释义见 [../docs/MUSE-INTEGRATION.md](../docs/MUSE-INTEGRATION.md)
   的"输出契约"一节。
5. **结束本轮**。循环本身不保存任何跨轮状态——状态都在服务
   器端。

---

## 异常处理

| 现象 | 机械层面的处理 |
|---|---|
| `KEY_FAIL` | 脚本在服务器端已自动尝试从 QQ 进程内存重扫取钥并重试一次，仍失败才报出此状态。收到后：先检查 QQ 是否仍在运行且已登录（见下"确认登录状态"）；QQ 正常而钥匙仍取不到时，手动重跑一次 `scan_key.py` / `strong_scan.py` 生成新 `key.json` |
| `ERROR` | 记录脚本输出的错误原文；多为副本或解密环节异常，检查工作目录空间与文件权限后重试一轮 |
| `qq_running=false` | 到 QQ 主机确认进程状态：`ps aux \| grep -i "/opt/QQ/qq" \| grep -v grep`（实际二进制是 `/opt/QQ/qq`，命令行带 `--relaunch` 等参数，按旧参数匹配永远找不到）。按你自己的部署方式拉起官方客户端 |
| 数据库长时间不更新 | 多为 QQ 掉线或掉登录。确认登录状态（见下）；若停在登录界面，不要代填密码、不要强行登录，交由账号本人处理 |

### （可选）人工确认登录状态时的界面操作要点

文字管线失效时，可临时通过虚拟桌面截图确认 QQ 是停在聊天列
表还是登录界面。以下是操作层面的通用教训，与任何业务规则
无关：

- 截图定位工具（如 visual grounding）返回的通常是 0–1000
  归一化坐标，点击前必须换算到实际屏幕像素（例：1280×800
  屏幕：x×1280/1000、y×800/1000），直接拿归一化值点必偏。
- 点击要拆开：先移动到位、短暂停顿，再分开按下与抬起（如
  xdotool 的 `mousemove --sync` → `mousedown` → `mouseup`
  分步执行）；一体式连点在 QQ 客户端里经常不切换会话。
- 一次没切换成功多半是点到了列表行间隙：定位群名文字、点行
  中心再试。
- 群公告等弹窗：先放大截图看清按钮文字再点；关闭一律点"取
  消"，绝不点"发布"之类的确认按钮。
- 全程只读：不发送、不删除、不做任何写操作。
